# План фронтенда (Web UI)

Черновик для разбора. Цель — заменить `Google Sheets` как UI: показывать
аналитику по стримам/играм/релизам/советам и управлять сервисом через сайт.
Интеграция — по [WEB_API.md](WEB_API.md) (FastAPI, `/api/v1`, cookie-сессии +
CSRF, Twitch OAuth).

Статус: **в работе**. Сделаны Фазы 0–5 (все write-действия: советы, игры,
релизы) и Twitch-авторизация — обычный веб-вход и **стримерский OAuth** с
расширенными правами (см. раздел 10). Осталось: разделы «Команды»/«Ивенты»/
«Интерактив», Фаза 6 (дашборд, отложено) и Фаза 7 — полировка (адаптив,
скелетоны, тесты, деплой). Ключевые решения зафиксированы (раздел 2),
оставшиеся вопросы — в разделе 8.

---

## 1. Контекст

- Бэкенд уже готов: `backend/main.py`, документация `/docs`, схема
  `/openapi.json`.
- Данные — зеркало листов Google Sheets: **ИГРЫ**, **СТРИМЫ**, **РЕЛИЗЫ**,
  **СОВЕТЫ** (+ справочники жанров/платформ).
- Аутентификация: Twitch OAuth, серверные cookie-сессии, токен на фронте не
  храним.
- Роли: `is_streamer`, `is_admin` (управляют правом на запись).
- Формат ответов: списки в обёртке `Page<T>` (`items/total/limit/offset`),
  ошибки в конверте `{detail:{code,message}}`.
- Даты — ISO 8601 **naive UTC**, приводим к локальному времени на фронте.
- Дизайн — **тёмная тема**, отдельная цветовая схема для каждого раздела
  (см. раздел 3).
- Один канал (**Tabula**); мультиканальность — возможно позже.
- Сайт русскоязычный, локализации на другие языки нет.
- Весь проект на **одном сервере**, бэкенд слушает локальный адрес
  (`127.0.0.1:8001`), наружу API не публикуется.

### 2.1 Про кодогенерацию типов (вопрос 13)

Бэкенд по адресу `/openapi.json` отдаёт машинную схему всех эндпоинтов и
полей. Инструмент `openapi-typescript` читает её и **автоматически** создаёт
TypeScript-типы (`GameView`, `Page<StreamView>` и т.д.). Тогда мы не пишем
интерфейсы руками и они не «разъезжаются» с бэкендом. Обновление — командой
вида `npm run gen:api` при запущенном бэкенде. **Рекомендую использовать.**
Альтернатива — писать типы вручную (больше ручной работы и риск ошибок).

## 3. Стек

### Ядро
- **React 19 + TypeScript + Vite 7**.
- **React Router v7** — маршрутизация.

### Работа с данными
- **TanStack Query** — серверное состояние: кеш, пагинация, инвалидация после
  мутаций, loading/error-состояния.
- **axios** — HTTP-клиент: `baseURL`, `withCredentials: true`, инъекция
  CSRF-заголовка, нормализация ошибок.
- **openapi-typescript** — генерация TS-типов из `/openapi.json`.

### UI и дизайн-система
- **Tailwind CSS** — утилитарная вёрстка и токены темы.
- **CSS-переменные на раздел** (`--section-bg`, `--card-bg`, `--accent`) —
  цветовая схема «переключается» на `<div data-section="...">`, Tailwind-классы
  читают переменные. Один каркас — четыре палитры.
- **shadcn/ui (Radix)** — dropdown, dialog, popover, tooltip, toggle, tabs.
- **lucide-react** — иконки интерфейса.
- **class-variance-authority + tailwind-merge** — варианты компонентов.
- **TanStack Table** (headless) — логика сортировки/фильтрации под кастомные
  «островки». (Опционально: если фильтрация на клиенте, можно и без неё.)

> Ant Design отклонён: навязывает свою тему и плотные таблицы, мешает
> кастомным «островкам» и четырём палитрам.

### Шрифты
- **@fontsource/montserrat** и **@fontsource/orbitron** — self-hosted (без
  внешних запросов, важно для локального сервера). Импорт в `styles/fonts.ts`.
- В Tailwind: `font-sans` → Montserrat, `font-social` → Orbitron.

### Вспомогательное
- **react-hook-form + zod** — формы и валидация.
- **dayjs** — даты (naive UTC → локаль).
- **ESLint + Prettier**, **Vitest + Testing Library**, **Playwright** (позже),
  **sonner** — тосты.

2. **Панель раздела** (левая, при вкладке «Статистика»): вертикально

3. **Подшапка раздела** — вторая строка, шире сетки, допускается

#### 4.2.1 Оформление «Админки» (реализовано)

- **Шапка раздела** — на всю ширину, над боковой панелью (как в «Статистике»):
  название раздела + пояснение.
- **Боковая панель** начинается ниже шапки: сверху **аватар канала**
  (`profile_image_url` из `user_profiles`, Tabula) — из `GET
  /api/v1/meta/channel`, с локальным запасным файлом
  (`public/images/tabula.png`), ниже — разделы админки.
- **Порядок разделов:** Управление → Telegram → Подключения (последним).
- **Палитра раздела «Telegram»:** фон `#171D21`, карточки `#242D33`, акцент
  `#2AABEE` (`[data-section='telegram']` в `src/index.css`).
- **Подразделы «Telegram»** — линия-переключатель под шапкой на всю ширину
  (`components/ui/SwitchLine.tsx`): **Старт стрима / Во время стрима / Конец
  стрима**. Первые два пока пустые. Активный подраздел — в query-параметре
  `?tab=`; при переходе в раздел без параметра открывается **«Конец стрима»**.

### 4.2.2 Страница игры (`/games/:id`) — оформление

Страница собирает данные из разных листов «Статистики» и показывает их
**тремя разнесёнными столбцами**. Без обводок и скруглений: разделены
**цветными полосами** — цвет полосы = цвет раздела-источника
(`--accent-games/streams/releases/recommendations/hltb` в `index.css`).

- **Шапка:** слева «СТРАНИЦА ИГРЫ» (как заголовки других листов), справа —
  стрелка «назад» и ссылки **ВСЕ ИГРЫ / ВСЕ РЕЛИЗЫ / ВСЕ СОВЕТЫ**; ссылка
  показывается только если игра присутствует в этом листе
  (`in_games` / `in_releases` / `in_recommendations` отдаёт бэкенд).
- **Первый столбик (общее):** обложка 48×48 + название крупным обычным
  шрифтом (не Orbitron), ниже описание (`description_ru`, иначе `description_en`),
  затем **ссылки строкой** — Steam (шрифт Orbitron, цвет как в листе «Игры»,
  `#66c0f4`) и HowLongToBeat (Orbitron, цвет листа HLTB, `--accent-hltb`),
  без подписи «Ссылки» и без подчёркивания; далее дата релиза (оранжевая
  полоса), жанры, платформы; **с отступом в строку** — блок «Время прохождения»
  со всеми временами HLTB (красная полоса). Без тегов, типа и slug.
- **Второй столбик (показатели):** ранг, часов, стримов. Далее:
  - «Понравилось» / «Пройдено» — **только если игра есть в листе «Игры»**
    (была на стримах), с отступом в строку от пункта «Стримов»;
  - «Интересно» — **только если игра есть в листе «Релизы»**;
  - блок «Рекомендуют» — **только если игры нет в листе «Игры»**, с отступом
    в строку от пункта выше.
- **Третий столбиц (стримы):** список стримов, где играли в игру, от новейших
  к самым старым (фиолетовая полоса): дата, название, длительность, ссылка на
  запись.

Столбцы — **прямоугольники с фоном островков (`--card-bg`) без обводки**;
границы между строками — цветные полосы по 2 px (**последняя строка тоже
подчёркнута**).

Время везде в формате «часов и минут» (`formatDuration` / `formatHltbTime`),
как в остальных листах и в команде бота.

**Бэкенд:** `GET /api/v1/games/{id}` отдаёт `release_date`,
`release_delta_days`, `description_ru`/`description_en`, `recommenders_list`
(с `display_name` и комментарием), `recommenders_count`, `interested`, все
времена HLTB (`hltb_id`, `hltb_main_story`, `hltb_main_extra`,
`hltb_completionist`, `hltb_coop`, `hltb_multiplayer`), список `streams` и
флаги присутствия в листах `in_games` / `in_releases` /
`in_recommendations` — с теми же условиями, что и у самих списков
(`backend/repositories/games.py`, `backend/schemas/game.py`).

### 4.2.3 Страница игры: раскладка по столбцам

- **Первый столбик (общее):** обложка 48×48 + название крупным обычным
  шрифтом, описание, ссылки **Steam** и **HowLongToBeat** (шрифт Orbitron, со
  значком «уходит наружу» — чтобы было видно, что они кликабельные), дата
  релиза, жанры, платформы, **ранг**, **часов**, и отметки «Пройдено» /
  «Понравилось» / «Интересно» (по условиям листов, с отступом в строку).
- **Второй столбик:** список всех стримов, где играли в игру, от новейших к
  самым старым; **количество — в заголовке списка** («Стримы (355)»).
- **Третий столбик:** блок «Время прохождения» (все времена HLTB) и список
  рекомендовавших (если игры нет в листе «Игры»).

## 4.3 Полировка интерфейса (реализовано)

- **ErrorBoundary** (`components/ui/ErrorBoundary.tsx`) — обёртка вокруг
  приложения: при ошибке рендера показывается понятное сообщение с кнопками
  «Попробовать снова» и «Обновить страницу» вместо белого экрана.
  Заодно добавлен простой компонент кнопки `components/ui/Button.tsx`.
- **Скелетоны** (`components/ui/Skeleton.tsx`) вместо спиннеров во всех
  табличных разделах: повторяется сетка колонок и строк, страница не
  «мигает» пустотой.
- **Адаптив:** на широких экранах — привычная таблица, на узких — карточки
  (`components/entity/EntityList.tsx`); боковая панель разделов скрывается и
  заменяется горизонтальной лентой (`components/layout/SectionBar.tsx`).
  Доработано: верхняя полоса (названия канала и вкладки прокручиваются, блок
  авторизации не сжимается), шапка раздела (чипы статистики в одну строку, кнопка
  действия — под ними), поля поиска на всю ширину, выпадающее меню фильтров не
  выходит за экран, список стримов на странице игры без вложенной прокрутки.
- **Тесты фронта:** юнит-тесты чистых функций на Vitest
  (`src/lib/*.test.ts`, `src/api/client.test.ts` — 46 тестов) и смоук-сценарии
  разделов на Playwright (`e2e/smoke.spec.ts` — 9 тестов, системный Chrome,
  без скачивания браузеров). Команды: `npm test`, `npm run test:e2e`.
- **Длинные списки на странице игры:** стримы по игре отдаются порциями
  (`GET /games/{id}/streams`, на странице сразу 50 и кнопка «Показать ещё»).

## 4.4 Серверные фильтры, поиск, сортировка

Поиск, фильтры, сортировка и пагинация выполняются **на сервере** — разделы
больше не грузятся целиком.

- Общий слой: `backend/repositories/list_query.py` (разбор параметров) и
  `backend/repositories/filters.py` (условия по тегам `tag:<значение>` и
  рекомендовавшим `rec:<логин>`, спец-теги стримов «Общение»/«Участники»/«IRL»).
- Ответ `Page<T>` расширен полями `total_all` (строк без фильтров) и
  `aggregates` (числа для шапки раздела).
- Значения тегов и рекомендовавших для меню фильтров отдают отдельные
  эндпоинты: `/games/filters`, `/streams/filters`, `/releases/filters`,
  `/recommendations/filters` — меню не зависит от текущей страницы.
- Переведены **все** разделы: Игры (535), Стримы (1345), Релизы (70),
  Советы (105), HowLongToBeat (536).
- Ранг игр считается по всем играм (оконная функция `row_number()`), а не по
  отфильтрованным — как было раньше.

> ⚠️ Массивы в query-параметрах отправляются повторяющимся ключом без
> скобок (`filters=a&filters=b`): по умолчанию axios ставит `filters[]=a`, а
> FastAPI такой параметр не видит — фильтры молча игнорируются. Поэтому в
> `api/client.ts` задан свой `paramsSerializer` (покрыт тестом).

### 4.2.4 Обложки игр

- Все обложки из `game_metadata_igdb.cover_url` — **квадратные** (со слегка
  скруглёнными углами) и **небольшие**: 45×45 (`CoverImage`,
  `GameCoverStrip`, страница игры). Раньше они сжимались в прямоугольники
  (`h-11 w-8`), из-за чего картинки искажались.
- В листе «Стримы» столбец «Игры» — **полоса обложек по шесть в ряд**
  (`grid-cols-6`, промежуток 16 px), дальше перенос на новую строку; между
  играми внутри строки — тонкая шеврон-стрелка (`ChevronRight`) в промежутке.
  Столбец шириной под шесть обложек.
- Сортировка по столбцу «Игры» — **по количеству игр на стриме** (и на
  клиенте, и на сервере: `count(stream_games)`).

> ⚠️ Массивы в query-параметрах отправляются повторяющимся ключом без
> скобок (`filters=a&filters=b`): по умолчанию axios ставит `filters[]=a`, а
> FastAPI такой параметр не видит — фильтры молча игнорируются. Поэтому в
> `api/client.ts` задан свой `paramsSerializer`.

### 4.5 Паттерн «островок»

- Каждый элемент — **отдельный блок одинакового размера в пределах раздела**
  (единый шаблон сетки, фиксированная высота строки).
- **Внешняя граница** — толстая, цвет `--accent`. **Внутренние разделители**
  между ячейками — тонкие, тот же `--accent` (сниженная непрозрачность).
- Фон островка `--card-bg`, фон вокруг `--section-bg`; скругление ~10px,
  мягкая тень.
- **Переполнение текста**: обрезка (`line-clamp`) + раскрытие при наведении
  (Radix Tooltip/Popover) — размер карточки не «прыгает».
- Компонент `EntityCard` + `EntityCard.Field`, палитра — из `data-section`.

### 4.6 Шрифты

- Montserrat — весь UI и контент (`font-sans`).
- Orbitron — названия соцсетей и подобные «брендовые» подписи (`font-social`).

### 4.7 Иконки

- Папка заказчика: **`frontend/public/socials/`** — `twitch.svg`,
  `telegram.svg`, `youtube.svg`, `boosty.svg`, `discord.svg`, `steam.svg`.
- Ссылки на них — из `/socials/<name>.svg`, чтобы не пересобирать проект при
  замене файлов.
- При необходимости другие картинки — в `frontend/public/images/`.

      ui/           # UI-кит: Pagination, FilterMenu, ConfirmDialog, StatChip…
      layout/       # TopBar, ChannelMenu, SectionPanel, SectionHeader, AppLayout

Заголовки вкладок и соцсети — из `config/*.ts`, чтобы добавлять разделы без
правки разметки.

### 5.2 Деплой (локально, один сервер)
- Бэкенд слушает `127.0.0.1:8001`, наружу не публикуется.
- Dev: Vite (`:5173`) с прокси `/api` → `127.0.0.1:8001`. Браузер видит всё
  как same-origin → CORS и cookie/CSRF работают без лишних настроек.
- Prod (позже, когда будет домен): статика собирается в `dist/`, отдаётся
  веб-сервером (nginx/Caddy) с того же хоста, `/api` проксируется на
  `127.0.0.1:8001`. Публичного CORS не требуется.

### 5.3 API-клиент
- `baseURL = VITE_API_BASE_URL` (по умолчанию `/api/v1` через прокси).
- `withCredentials: true`.
- Для не-GET читаем cookie `backend_csrf_token` → заголовок `X-CSRF-Token`.
- `401` → сброс `/auth/me` → редирект на вход; `403 csrf_failed` →
  перечитать cookie.

### 5.4 Темизация, пагинация, роли, даты
- Тема — через `data-section` (см. 4.1).
- `usePaginatedQuery` поверх `limit`/`offset`, синхронно с URL.
- `useAuth()` → `user`, `is_streamer`, `is_admin`. **Чтение открыто всем без
  входа;** гейтим только мутации (кнопки/тумблеры/формы) и маршрут `/admin`.
  Неавторизованному при попытке изменить — подсказка войти через Twitch.
- `dayjs.utc(x).local()` для отображения; готовые `hours`/`delta_days` не
  пересчитываем.

#### 6.3.1 Добавление игры по ссылке HowLongToBeat

Окно «Добавить игру» (`features/hltb/AddHltbModal.tsx`):

1. Админ вставляет ссылку `https://howlongtobeat.com/game/<id>` (принимается и

   HLTB периодически рвёт соединение) → поиск игры в базе (по `hltb_id`, затем
   по названию) → предпросмотр: название, все времена, найденная игра в базе.
3. Пользователь подтверждает («Добавить») → `POST /api/v1/hltb`:
   `add_hltb_game_by_url()` — пишет `game_metadata_hltb`
   (`apply_hltb_patch`), обновляет IGDB-метаданные (`_apply_igdb_enrichment` —
   общий с командой `!hltb`), при необходимости создаёт игру в `games`.

#### 6.2 После добавления — переход к игре

Добавленная игра не всегда видна: в «Советах» сорт по умолчанию — по числу
рекомендаций, поэтому новая строка уезжает на последние страницы.

- После мутации инвалидируются **оба** списка — `['recommendations']` и
  `['releases']` (`useRecommendations.ts`).
- Игра передаётся в списки через query-параметр **`focus=<game_id>`**.
- Хук `useFocusGameRow` (`hooks/useFocusGameRow.ts`): пролистывает список на
  нужную страницу (через `?offset=`), **подсвечивает** строку акцентом
  (`EntityTable` → `highlightedRowKey` + `data-row-key`) и плавно скроллит к
  ней. Если игра скрыта поиском/фильтрами — поиск и фильтры сбрасываются.
- Если нужный раздел уже открыт — фокус ставится на текущей странице, иначе
  выполняется переход `navigate('/releases?focus=42')`. Кнопки «Релизы»/
  «Советы» в окне успеха ведут туда же.

#### 5.0 Права на отметки (решение)

Отмечать «Понравилось» / «Пройдено» / «Интересно» может **только
администратор** (`is_admin`). Остальные пользователи видят отметки, но не могут
их менять.

- Бэкенд: зависимость `AdminDep` вместо `StreamerOrAdminDep` в
  `backend/routers/games.py` и `backend/routers/releases.py`
  (`StreamerOrAdminDep` больше не используется нигде).
- Фронтенд: без прав — статичная иконка; с правами — кнопка
  (`aria-pressed`). Компонент `components/ui/FlagToggle.tsx`.
- Отметки пишутся в таблицу `streamer_games` по `streamer_id` из настроек
  (канал владельца), независимо от того, кто отметил.
- Обновление **оптимистичное**: флаг меняется сразу, при ошибке возвращается
  прежнее значение, показывается тост (`useUpdateGameState`,
  `useSetReleaseInterested`).
- Тумблеры есть и в списке, и на странице игры (`GameDetailPage`).

#### 5.1 Отметка «Интересно» = рекомендация канала

Постановка: при отметке «Интересно» в разделе «Релизы» должна создаваться
рекомендация этой игры **от Tabula** с заметкой
**«Ожидаемая новинка по версии Tabula»** (и исчезать при снятии отметки).

- `backend/routers/releases.py`: `PATCH /releases/{game_id}/interested` после
  апсерта флага вызывает `set_release_interest_recommendation(...)`.
- `pipeline/load/load_recommendations.py`:
  `set_release_interest_recommendation(session, game_id, user_login=…, note=…,
  interested=…)`:
  - `interested=True` — создаёт рекомендацию (если её нет) с заметкой; уже
    существующую рекомендацию не трогает (чужой комментарий не перезаписывается,
    пустой — дополняется);
  - `interested=False` — удаляет **только** рекомендацию с этой заметкой
    (созданную данной механикой), ручные рекомендации остаются.
- Логин/имя канала берутся из настроек: `RECOMMENDATIONS_STREAMER_LOGIN`
  (`tabula`) и `RECOMMENDATIONS_STREAMER_DISPLAY_NAME` (`Tabula`), заметка
  собирается как `f"Ожидаемая новинка по версии {display_name}"`.
- Псевдорекомендация Twitch («Ожидаемая новинка по версии Twitch») — отдельный
  механизм импорта IGDB, он не затрагивается.
- После смены отметки фронт инвалидирует и `['releases']`, и
  `['recommendations']` — чип «Tabula» появляется в ячейке «Рекомендуют», а
  после релиза игра попадёт в «Советы» с рекомендацией Tabula.

#### 5.1 Советы: что сделано сверх исходного плана

- **Окно «Предложить игру»** вместо инлайн-формы: поиск по IGDB с выбором

  «ещё N» — ссылки на `/games/:id`; тултип показывает комментарий
  (`recommendation_note`).
- **Фильтр по рекомендовавшему** — ключ `rec:<login>` в `FilterMenu`.
- **Комментарий сквозным путём**: `RecommendationAddBody.note` →
  `recommend_game(note=…)` → `_db_add_recommendation` → `recommendation_note`
  → тултипы в UI.
- **Twitch-рекомендации** — `refresh_recommendation_lifecycle()`
  (`services/recommendations_service.py`, окно `UPCOMING_RELEASE_WINDOW_DAYS
  = 2`): рекомендация от twitch удаляется, когда релиз прошёл больше двух
  дней назад (сама игра остаётся). Вызывается в `GET /recommendations`.
- **Игра не удаляется при снятии последней рекомендации** (убран блок
  удаления `Game` в `pipeline/load/load_recommendations.py`).
- **Удаление чужой рекомендации** — `DELETE /recommendations/{game_id}?user_login=…`:
  свои удаляет любой, чужие — только админ (иначе 403).
- **Эндпоинт поиска пользователей** — `GET /api/v1/users/search`
  (`backend/routers/users.py`, `backend/schemas/user.py`).

## 10. Twitch-авторизация (веб-вход и стримерский OAuth)

Реализовано два независимых потока OAuth на одном `redirect_uri`; поток
различается **префиксом OAuth-state** (`login.*` / `streamer.*`), поэтому второй
redirect URI в Twitch Dev Console регистрировать не нужно.

### 10.1 Обычный веб-вход
- Эндпоинты: `GET /auth/login` → `GET /auth/callback` → cookie-сессия;
  `GET /auth/me`, `POST /auth/logout`.
- Scope: `user:read:email`.
- Токен Twitch хранится в БД (`twitch_authorizations`, ключ `user_id`), не на
  фронте. Сессия — серверная cookie (`web_sessions`) + CSRF-cookie.
- Пользователь создаётся/обновляется в `users` + `user_profiles`; роль
  `is_streamer`/`is_admin` выводится из `STREAMER_LOGINS`/`ADMINS`.

### 10.2 Стримерский вход (расширенные права)
- Эндпоинт: `GET /auth/streamer/login` (тот же callback) → токен с расширенными
  scope сохраняется **в отдельную таблицу** `twitch_streamer_authorizations`
  (ключ `user_id`), чтобы обычный вход его не затирал. Веб-сессия при этом НЕ
  создаётся.
- Scope задаётся в `backend/config.py` (`twitch_streamer_scope`, property
  `twitch_streamer_scopes`); по умолчанию —
  `channel:read:redemptions channel:manage:redemptions` (баллы канала; набор
  расширяем).
- Пускаются только логины из `STREAMER_LOGINS` (`config/settings.py`, env
  `STREAMER_LOGINS` через запятую; по умолчанию — `RECOMMENDATIONS_STREAMER_LOGIN`).
  Чужой логин → редирект `?streamer=denied`.
- Ротация токена: `backend/security/twitch_tokens.py`
  (`get_twitch_access_token`, `get_streamer_access_token`) — обновляет пару
  заранее, под блокировкой строки.
- Статус для админки: `GET /auth/streamer/status` (только `is_admin`) —
  запрашиваемые scope и по каждому логину `connected`/`expires_at`
  (`backend/schemas/auth.py`: `StreamerAuthStatus`, `StreamerAuthorizationView`).
- Модель/миграция: `database/models.py` (`TwitchStreamerAuthorization`),
  `alembic/versions/0011_streamer_authorizations.py`.
- Фронт: `features/auth/api.ts` (`goToStreamerLogin`, `getStreamerStatus`),
  хук `useStreamerStatus`, раздел в `pages/AdminPage.tsx` («Расширенные права
  стримера» + кнопка «Подключить права»). Возврат `?streamer=success|denied`
  обрабатывается в `AuthProvider` (тост + инвалидация статуса).

> ⚠️ Обычный вход и вход в бота используют общий `CLIENT_ID`/`CLIENT_SECRET`:
> Disconnect приложения или смена пароля Twitch отзовут оба гранта. Отдельное
> Twitch-приложение под веб-вход — возможное улучшение (не сделано).

## 11. Запуск локально

Требования: PostgreSQL на `localhost:5433` (БД `streamflow`), Python с
зависимостями, Node.js 24+.

### 11.1 Бэкенд (FastAPI, порт 8001)

Своего venv у репозитория нет — используется venv из репозитория бота
(`mishgan-twitch-bot/.venv`, общие зависимости) либо любой свой. Из корня
`streamflow`:

```powershell
# пример: активируйте venv и запустите uvicorn
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8001
```

Либо через исполняемый файл venv (подставьте свой путь):

```powershell
& "<путь-к-python>\Scripts\python.exe" -m uvicorn backend.main:app --host 127.0.0.1 --port 8001
```

Без `--reload` (после правок кода — перезапуск вручную). Health-check:
`http://127.0.0.1:8001/api/v1/health`, документация — `/docs`.

Миграции (если менялась схема; `alembic.ini` — локальный, в `.gitignore`):

```powershell
python -m alembic upgrade head
```

### 11.2 Фронтенд (Vite, порт 5173)
Из папки `frontend`:

```powershell
npm install        # один раз
npm run dev        # dev-сервер с прокси /api → 127.0.0.1:8001
```

Открывать **`http://localhost:5173/`** (Vite слушает IPv6 `::1`; не `127.0.0.1`).
Перегенерация типов при запущенном бэкенде: `npm run gen:api`.

### 11.3 Переменные окружения (`.env` в корне `streamflow`)
- `DATABASE_URL` — подключение к PostgreSQL;
- `TWITCH_CLIENT_ID`/`CLIENT_SECRET` (или алиасы `CLIENT_ID`/`CLIENT_SECRET`) —
  приложение Twitch для веб-входа;
- `TWITCH_REDIRECT_URI` = `http://localhost:5173/api/v1/auth/callback`;
- `BACKEND_FRONTEND_URL` = `http://localhost:5173/`;
- `STREAMER_LOGINS` (опц.) — логины с доступом к расширенным правам;
- `ADMINS` — логины администраторов.

Redirect URI должен быть добавлен в Twitch Dev Console приложения.

## 12. Практические заметки по разработке

### 12.1 Проверки фронтенда

```powershell
cd frontend
npm run typecheck   # tsc -b  — реальная проверка типов
npx oxlint          # линтер
npx prettier --check src
npm run build       # tsc -b && vite build
```

> ⚠️ `npx tsc --noEmit` **ничего не проверяет**: корневой `tsconfig.json`
> — solution-файл (`"files": []` + `references`), поэтому без `-b` компилятор
> не заходит в `tsconfig.app.json`. Используйте `npm run typecheck` (`tsc -b`).
> `vite build` тоже типы не проверяет — только `tsc -b` это делает.

`src/api/schema.d.ts` генерируется и не форматируется — он в `.prettierignore`.

### 12.2 После правок бэкенда

1. Перезапустить uvicorn (без `--reload`).
2. `npm run gen:api` — перегенерация `src/api/schema.d.ts` с запущенным
   бэкендом.
3. `npm run typecheck` — появятся/исчезнут типы.

### 12.3 Кодировка файлов

Файлы — **UTF-8 без BOM**. PowerShell 5.1 читает файлы без `-Encoding UTF8` в
системной ANSI-кодировке (на русской Windows — **CP1251**), поэтому
`Get-Content` + `Set-Content` без явной кодировки **ломает кириллицу**
(«кракозябры»). Правьте исходники только через редактор/инструменты с
явным UTF-8 (`read`/`edit`/`write`, prettier, oxlint).

### 12.4 Ошибки, на которые стоит обратить внимание

- `tsc -b` может молча «проходить» при неверном tsconfig — сверяйтесь с
  разделом 12.1.
- `git grep` не находит файлы в `frontend/` — папка пока не добавлена в
  индекс (untracked). Для поиска по ней используйте ripgrep/`Select-String`,
  а не `git grep`.
